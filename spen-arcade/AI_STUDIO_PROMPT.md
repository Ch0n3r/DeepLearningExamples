# Промпт для Gemini в AI Studio

Скопируй текст ниже в aistudio.google.com/apps. Он описывает архитектуру и
жёстко фиксирует границы, которые Gemini нельзя нарушать — иначе модель
любит переписать слой ввода «по-своему» и сломать работу с S Pen.

---

## Промпт

> Я делаю аркаду для Android, управляемую наклоном стилуса Samsung S Pen.
> Веб-часть работает внутри WebView, а нативный Kotlin-мост уже написан и
> отдаёт состояние пера в JS. Твоя задача — расширять игровой контент,
> НЕ трогая слой ввода.
>
> **Стек:** TypeScript + Canvas2D, без игровых движков и внешних зависимостей.
> Vite, сборка в один HTML-файл.
>
> **Неприкосновенный контракт ввода.** Весь геймплей читает только это:
> ```ts
> interface PenState {
>   tiltX: number;         // [-1;1], + вправо
>   tiltY: number;         // [-1;1], + вниз
>   magnitude: number;     // модуль наклона [0;1]
>   angle: number;         // направление наклона, рад
>   button: boolean;       // кнопка стилуса зажата
>   hover: boolean;        // перо над экраном
>   hoverX: number;        // [0;1] по ширине экрана
>   hoverY: number;        // [0;1] по высоте
>   hoverDistance: number; // 0 = касание, 1 = край зоны hover
>   pressure: number;
>   source: 'native' | 'pointer' | 'gyro' | 'mouse';
> }
> ```
> Никогда не обращайся к `window.SPenNative`, `DeviceOrientationEvent` или
> `PointerEvent` напрямую из игрового кода — этим занимается `PenInput`.
>
> **Контракт сцены.** Каждая мини-игра реализует:
> ```ts
> interface Scene {
>   name: string;
>   enter(ctx: SceneContext, payload?: unknown): void;
>   update(ctx: SceneContext, dt: number): void;   // dt ВСЕГДА 1/60
>   render(ctx: SceneContext, alpha: number): void; // alpha для интерполяции
>   exit?(ctx: SceneContext): void;
> }
> ```
> `update` вызывается с фиксированным шагом, `render` — раз в кадр. Не клади
> игровую логику в `render` и не читай `performance.now()` в `update`.
>
> **Правила, которые важнее красоты:**
> 1. Наклон задаёт УСКОРЕНИЕ или УГЛОВУЮ СКОРОСТЬ, а не позицию. Исключение —
>    рисование рун, там нужна позиция.
> 2. Никаких аллокаций в `update`/`render`: пулы объектов, `swap-remove`
>    вместо `splice`, переиспользуемые векторы.
> 3. Каждая мини-игра играбельна мышью — иначе её нельзя отладить в браузере.
> 4. Все тексты интерфейса на русском.
> 5. Кнопка стилуса — ровно одно основное действие на игру. Долгое
>    удержание — второе, не больше.
>

## Как этим пользоваться

1. Создай приложение в AI Studio, вставь промпт.
2. Приложи файлы из `web/src/` — Gemini увидит существующие контракты и
   будет держаться их.
3. Каждую новую мини-игру проси **одним файлом** в `src/games/` —
   так проще ревьюить и откатывать.
4. Готовую сборку клади в `android/app/src/main/assets/game/index.html`.

## Что Gemini регулярно ломает — проверяй в первую очередь

- Пишет `requestAnimationFrame` внутри сцены. Цикл один, он в `Engine`.
- Читает `pen.tiltX` и сразу присваивает в позицию — управление становится
  «мышиным» и теряет ощущение полёта.
- Заводит `new Vec2()` внутри цикла частиц. На телефоне это видно как фризы.
- Забывает про `ctx.save.invertY` — настройка есть, но не применяется.
- Использует `dt` из `render` вместо фиксированного шага.
